# Project setup.sh Contract

Every code project in `~/documents/code-projects/` should provide a `setup.sh` at its root.
The `projects` Ansible role clones each repo and runs this script to bring the project to a working state.

## Contract

```bash
#!/usr/bin/env bash
set -euo pipefail
```

### Requirements

- **Idempotent**: Safe to run multiple times. Skip work already done.
- **Portable paths**: Use `$HOME`, never hardcode `/home/<user>`.
- **Run from project root**: The script is always invoked as `./setup.sh` from the project directory.
- **Exit codes**: Exit 0 on success, non-zero on failure.
- **`--no-start` flag**: When passed, install and enable services but do not start them. The Ansible `projects` role uses this to batch service starts after all projects are set up.

### Secret injection

Use 1Password CLI (`op inject`) to generate `.env` from `.env.tpl`:

```bash
if command -v op &>/dev/null && op account list &>/dev/null 2>&1; then
    op inject -i .env.tpl -o .env
else
    if [[ ! -f .env ]]; then
        cp .env.tpl .env
        echo "[WARN] 1Password not available. Copied .env.tpl -> .env with placeholder values."
        echo "       Edit .env manually before starting services."
    fi
fi
```

- `.env.tpl` — committed to git. Contains `op://DevKeys/Item/field` references for secrets and literal values for non-secret config.
- `.env` — gitignored. Generated by `op inject` or copied as fallback.

### Systemd services

If the project runs as a service:

1. Copy unit files to `~/.config/systemd/user/`
2. Run `systemctl --user daemon-reload`
3. Run `systemctl --user enable <service>` (always)
4. Run `systemctl --user start <service>` only if `--no-start` was NOT passed

Use `EnvironmentFile=` in unit files pointing to the project's `.env`, not hardcoded `Environment=` lines.

### Dependencies

The script installs its own dependencies:

- **Python**: Create venv, `pip install -r requirements.txt`
- **Node**: `pnpm install` or `npm install`
- **Docker**: `docker compose build` if needed

Do not assume tools are globally installed beyond what the Ansible `dev-tools` role provides (git, python3, pip, node, npm, pnpm, docker).

## .env.tpl format

```bash
# Non-secret config (literal values)
OLLAMA_URL=http://10.0.20.214:11434
LOG_LEVEL=INFO

# Secrets (1Password references)
JWT_SECRET=op://DevKeys/Engram/jwt-secret
API_KEY=op://DevKeys/My Item/field-name
```

## Template

A minimal setup.sh:

```bash
#!/usr/bin/env bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
cd "$SCRIPT_DIR"

NO_START=false
[[ "${1:-}" == "--no-start" ]] && NO_START=true

# -- Secrets ------------------------------------------------------------------
if command -v op &>/dev/null && op account list &>/dev/null 2>&1; then
    op inject -i .env.tpl -o .env
    echo "[OK] Secrets injected from 1Password"
else
    if [[ ! -f .env ]]; then
        cp .env.tpl .env
        echo "[WARN] No 1Password session. Copied .env.tpl -> .env (edit manually)"
    fi
fi

# -- Dependencies -------------------------------------------------------------

# -- Build (if needed) --------------------------------------------------------

# cp systemd/*.service "$HOME/.config/systemd/user/"
# systemctl --user daemon-reload
# systemctl --user enable my-service.service
# if [[ "$NO_START" == false ]]; then
#     systemctl --user start my-service.service
# fi

echo "[OK] Setup complete"
```
